# 界面信息层级

HFLive Auth 的页面服务三个具体任务：成员登录、成员管理自己的资料、管理员管理成员与应用。协议、部署、状态机和运营规则留在 `docs/`；界面只显示用户当前决策需要的说明、错误和后果。

## 参考与取舍

- [Clerk Account Portal](https://clerk.com/docs/guides/account-portal/overview) 将登录与个人资料分成独立入口，并在完成认证后返回发起应用。HFLive Auth 沿用单独登录页和个人资料页，但只展示实际启用的用户名/邮箱与密码路径，不展示未实现的注册或社交登录入口。
- [Auth0 Universal Login](https://auth0.com/docs/customize/login-pages/universal-login) 将登录流程与页面文案集中管理，并允许按登录步骤调整提示。HFLive Auth 的登录、邮件验证码和授权确认各自只说明眼前动作；风险验证的解释放在验证码步骤。
- [Atlassian Administration](https://support.atlassian.com/organization-administration/docs/explore-an-atlassian-organization/) 按成员和应用组织管理信息。HFLive Auth 按应用、成员、邀请、操作记录划分独立页面；列表、创建和单项设置分别承载各自任务。
- [Google Account 个人信息](https://support.google.com/accounts/answer/27442) 从头像或姓名当前值进入独立编辑步骤，完成选择、裁剪或输入后保存；[Vercel Account Management](https://vercel.com/docs/accounts) 将账号资料与认证设置集中在同一入口。资料页在头像、显示名、用户名和邮箱的当前值旁提供更改入口，编辑时打开聚焦弹窗；邮箱验证和头像裁剪只在弹窗中出现。

上述是信息架构参考，不复制这些产品的注册、组织切换、计费或权限模型。HFLive Auth 仍只允许管理员邀请成员、审批应用。

## 页面约定

| 页面 | 首要动作 | 保留在界面的必要信息 |
| --- | --- | --- |
| 首页 | 访客登录；已登录成员管理资料；管理员进入后台 | 当前登录账号、首次使用的邀请入口提示 |
| 登录 | 输入用户名或邮箱和密码 | 错误反馈、找回密码；风险验证在下一步说明 |
| 个人资料 | 更新显示名、头像、用户名和邮箱 | 当前值、验证状态、保存结果；从对应资料行打开弹窗修改，保留返回发起应用的入口 |
| 管理后台 | 查看应用与成员状态，按需创建或编辑 | 状态、操作、保存后的凭据一次性展示和撤销后果 |

身份姓名区域把用户可修改的显示名置于主字号，下一行显示 `@登录用户名`。账号类型和身份资料只在管理员本人的资料页显示；普通用户无需看到这些管理字段。管理员从成员列表进入单个成员资料页，编辑身份标签和真名。

资料页只显示当前值和贴近当前值的更改入口；弹窗负责表单、验证和裁剪。弹窗打开后焦点进入编辑控件，Esc 可关闭，保存时禁止关闭。反馈以独立通知显示，不向概览插入状态块。

敏感操作的后果必须贴近按钮或确认步骤。技术字段（redirect URI、scope、webhook 事件类型）只在管理员编辑区出现；成员入口不承担项目文档功能。

页面级返回入口统一使用标题左侧的左箭头，提供至少 44×44px 点击区域、悬停提示、明确的屏幕阅读器名称和键盘焦点。资料页按已校验的来源返回应用，无来源时返回首页；管理后台与成员邀请页沿用同一形式。

个人资料页顶部只保留返回箭头与页面标题，不重复展示品牌名称或图标。

## 品牌图标

favicon 使用暖白圆角底上的石墨色几何 H，斜向横梁延续原图标的斜带形态，表达 HFLive 及应用间的身份连接。采用固定双色，在深浅浏览器背景中保持一致；图形不依赖字体、外部资源、渐变或滤镜。

`src/app/icon.svg` 是独立 SVG，由 Next.js metadata route 提供。首页和登录页的 `BrandMark` 使用相同的内联几何与颜色，桌面保持 28px、手机 26px 尺寸；更新时两处需同步，避免从静态资源 CDN 的 CSS 请求根路径图标。新旧对比与 16/20/24/32px 深浅背景预览见 [SVG 设计预览](../design/favicon-preview.svg)。


## 2026-10 视觉系统

本轮按用户反馈移除绿色霓虹、辉光、全页网格和玻璃面板，采用哑光石墨底与暖白文字。保留 H 的斜向横梁，同时统一 favicon、内联标记和品牌插画的颜色。

- [Linear 的界面更新](https://linear.app/now/behind-the-latest-design-refresh) 提供层级参考：让导航和辅助说明退后，把当前任务放在视觉中心。
- [Vercel Geist 排版](https://vercel.com/geist/typography) 提供尺度参考：区分标题、内容、标签与辅助说明，用统一节奏组织高密度界面。这里只借鉴设计原则，不引入第三方 UI 依赖。

### 颜色与材质

| 用途 | 色值 / 规则 |
| --- | --- |
| 页面底色 | `#191918` |
| 表面 / 弹窗 | `#20201e` / `#272724` |
| 主文字 / 次文字 | `#eeece6` / `#aaa89f` |
| 主操作 | 暖白 `#ece9e2`，深色文字 |
| 局部强调 | 陶土米色 `#e8c5ad`，用于链接、焦点与少量几何细节 |
| 状态 | 成功用灰绿色，错误用低饱和珊瑚色；同时保留文字说明 |
| 边界 | 细实线、小圆角；仅弹窗和浮动通知使用少量投影，不使用模糊或辉光 |

共享令牌与公共组件样式维护在 `src/app/globals.css`，资料页布局维护在 `src/app/profile/profile.css`。不追加相互覆盖的旧主题样式；主操作色与语义状态色分开。

### 页面布局

- 首页：双栏账号入口，按会话呈现登录、个人资料与管理入口；低对比度几何 H 只作为品牌装饰，不代表任何认证状态。
- 登录：桌面左侧品牌文字与插画直接排在页面底色上，右侧为输入区；不使用包围品牌或表单的大卡片。手机隐藏插画，让表单完整显示。找回密码、验证、重置、邀请、授权和错误页复用 `AuthFrame`，保留各自业务步骤。
- 个人资料：沿用标题左侧返回箭头，不重复品牌；基本资料与登录安全通过留白和细分隔线分组，桌面采用左侧说明、右侧资料行，手机顺序堆叠。所有修改仍在聚焦弹窗完成，来源应用回跳和密码直达参数保持原有校验。
- 管理后台：`/admin` 转到应用列表。应用、成员、邀请和操作记录使用真实页面导航与当前页标识，各页只查询和展示自己的内容。保留吸顶导航、开放底色、紧凑列表和细分隔线，避免同时加载多个栏目。
- 应用：`/admin/applications` 每页 15 项，可按名称或标识搜索。`/admin/applications/new` 专门创建应用，成功后先聚焦显示一次性凭据，确认保存后进入该应用。`/admin/applications/[clientId]` 再按登录设置、事件通知、凭据与状态切换，每次只呈现一项设置。
- 成员：`/admin/members` 每页 15 人，可按显示名、用户名或邮箱搜索。列表只保留身份、角色、状态；在 `/admin/members/[userId]` 修改用户名、身份资料和状态。手机继续使用紧凑行，不把每个人的所有编辑表单铺开。
- 操作记录：`/admin/activity` 每页 20 条，可按操作类型搜索，按时间从新到旧呈现。状态同时使用文字与颜色，不增加外围卡片。
- 邀请：`/admin/invitations` 每页 15 条，区分待接受和历史记录，可按邮箱或用户名搜索；所有仍保留的历史记录均可翻页查阅。发送邀请移到 `/admin/invitations/new`，选填身份资料按需展开。发送成功保留明确结果和继续邀请/查看记录入口；撤回需要就地确认，并更新当前列表与总数。

搜索、邀请筛选、页码和应用设置子页存入 URL，支持刷新、直接访问及浏览器前进后退；新搜索从第一页开始，翻页保留搜索与筛选，清除邀请搜索保留当前状态筛选。进入详情后，标题左箭头返回原搜索和页码；保存后刷新服务端列表，避免返回时看到旧数据。页码越界时收敛到有效范围，零条结果显示空状态。未登录访问管理页面时，通过现有 `callbackURL` 流程在登录后返回该页面及其查询条件，不改变回跳白名单、会话或 OIDC 协议。每个管理页面在读取数据前复核 `ACTIVE + ADMIN`，不能仅依靠共享布局检查权限；查询只选取当前视图需要的字段，不向列表发送密钥。

### 可访问性与验收

全站提供跳到主要内容入口、可见键盘焦点、可读错误面板；手机输入字号至少 16px。输入框使用 `#6c6a61` 边界，与输入底色 `#1b1b19` 对比度为 3.18:1，与面板底色 `#20201e` 为 3.01:1。次文字与页面底色对比度为 7.38:1。按钮与资料修改入口保留足够触控面积，动画只有短暂颜色过渡并遵从 `prefers-reduced-motion`。视觉调整不改 issuer、cookie、认证校验、权限、数据库或接入应用契约。

验收覆盖 1440px、390px 和 320px，检查页面溢出、键盘登录与焦点、错误态、显示名保存及弹窗关闭；认证公共布局调整同时执行完整 OIDC smoke。具体执行结果在开发进度与开发记录中维护。
